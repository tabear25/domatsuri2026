# どまつり 2026 演舞ハシゴ判定ページ

2026年8月30日（日）の第28回にっぽんど真ん中祭りで、見たい2チームの演舞を
両方見に行けるかを当日スマホで判断するための個人用ページ。

見たい2チームの全演舞を時系列に並べ、隣り合う演舞のあいだを
「両方いけるか」で4段階に判定し、各会場へワンタップで道案内を開始できる。

## ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | ページの器。`data.js` → `app.js` の順に読むだけ |
| `data.js` | **編集するのはここだけ**。会場マスタ・チーム・演舞スケジュール・計算の係数 |
| `app.js` | 徒歩時間の計算・4段階判定・描画・Googleマップ URL の組み立て |
| `styles.css` | 屋外のスマホで読むための高コントラストなスタイル |
| `tests.html` / `tests.js` | 判定ロジックの自己検証。ブラウザで開くだけで走る |
| `vercel.json` | キャッシュ無効化。当日の直前修正が確実に反映されるようにするため |

ビルドは不要。Node も npm もフレームワークも使っていない。

## 動かす

`index.html` をダブルクリックするだけで動く（`file://` で完結する）。
データを `fetch` ではなく `<script src="data.js">` で読んでいるのが理由で、
これは意図的な設計。ローカルサーバーは要らない。

### 日付タブ

画面上部に 8/28(金) / 8/29(土) / 8/30(日) のタブがあり、タップで表示する日を
切り替えられる。各タブにはその日の演舞件数が出る。

- 開いたときに選ばれる日は、**今日が開催日ならその日**、そうでなければ
  `defaultDate`（8/30）
- 実際の今日にあたるタブには ● が付く
- **選んだ日が実際の今日のときだけ**、「次の演舞まで◯分」「終わった演舞のグレーアウト」
  「次はここ」が働く。別の日を見ているときは全カードが通常表示になる
- タブは `?day=2026-08-29` という普通のリンクなので、リロードしても選択が残る

### 動作確認用のクエリ

| クエリ | 効果 |
|---|---|
| `?day=2026-08-29` | 表示する日（タブの選択そのもの） |
| `?now=14:35` | 現在時刻を上書きする |
| `?today=2026-08-30` | 今日の日付を上書きする |

例: `index.html?day=2026-08-30&today=2026-08-30&now=13:20`
（8/30 を当日として、13:20 時点の見え方を再現する）

`?now` か `?today` を使っている間は画面上部に黄色い「テスト表示中」バナーが出る。
本番でこのバナーが出ていたら URL からクエリを外すこと。`?day` だけなら出ない。

## スケジュールを入れる

`data.js` の `teams` と `performances` を書き換える。

```js
teams: [
  { id: "team1", name: "実際のチーム名", color: "#c2410c" },
  { id: "team2", name: "実際のチーム名", color: "#1d4ed8" },
],

performances: [
  { teamId: "team1", venueId: "hisaya_main", start: "14:20", end: "14:30" },
  { teamId: "team2", venueId: "oasis21",     start: "15:00", end: null },
],
```

- `venueId` は `venues` のキーをそのまま使う（`hisaya_main`, `oasis21` など）
- `end` がわからない演舞は `null` にする。`defaultDurationMin`（既定10分）で
  補われ、画面に「終了は推定」バッジが出る
- 書き換えたら `tests.html` を開いて全件パスすることを確認する。
  存在しない会場ID・中止会場の参照・時刻の書き間違いは、
  ページ上部に赤い警告として出る

### 終了時刻がわからないときの考え方

余裕 = 次の開始 − 前の終了 − 徒歩時間 なので、**演舞時間を短く見積もるほど
余裕が大きく出る**。つまり短すぎる既定値は「行けるはずが間に合わない」という
最悪の方向に外れる。`defaultDurationMin` は実際より少し長めにしておく。

## 判定のしくみ

```
徒歩見積もり = ceil( 会場間の直線距離 × 1.3 ÷ 分速80m )   ※同じ会場なら0分
余裕         = 次の開始 − 前の終了 − 徒歩見積もり
```

| 余裕 | 表示 |
|---|---|
| 20分以上 | ☀️😄 ばっちり |
| 10〜19分 | ⛅️😊 行ける |
| 0〜9分 | 🌧️😐 ギリギリ |
| 0分未満 | ⛈️😢 むずかしい |

迂回係数 1.3 は、直線距離のままだと久屋大通公園（南北1km超）や地下街経由の
移動を過小評価するための補正。`data.js` の `detourFactor` で変えられる。

**この見積もりは徒歩のみ。** 名駅↔栄のように地下鉄なら数分で着く区間も
徒歩換算で出る。そのため各判定バンドには Google マップの実測ルートへの
リンクを置いてある。

- `🚶 徒歩ルート` … 移動がある区間すべてに出る
- `🚇 電車ルート` … 直線距離が `transitHintMeters`（既定1200m）を超える区間だけに出る

顔文字の判定は徒歩基準のまま変えていない。ギリギリの区間や遠い区間は、
このリンクから Google の実測を見て最終判断する。`detourFactor` の 1.3 が
妥当かどうかも、徒歩ルートの実測値と見比べれば検証できる。
