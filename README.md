# どまつり 2026 演舞ハシゴ判定ページ

2026年8月30日（日）の第28回にっぽんど真ん中祭りで、見たい2チームの演舞を
両方見に行けるかを当日スマホで判断するための個人用ページ。

見たい2チームの全演舞を時系列に並べ、隣り合う演舞のあいだを
「両方いけるか」で4段階に判定し、各会場へワンタップで道案内を開始できる。

## ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | ページの器。`data.js` → `app.js` の順に読むだけ |
| `data.js` | **編集するのはここだけ**。会場マスタ・チーム・演舞スケジュール・駅間の所要時間・計算の係数 |
| `app.js` | 移動時間（徒歩と電車）の計算・4段階判定・描画・Googleマップ URL の組み立て |
| `styles.css` | 屋外のスマホで読むための高コントラストなスタイル |
| `tests.html` / `tests.js` | 判定ロジックの自己検証。ブラウザで開くだけで走る |
| `vercel.json` | キャッシュ無効化。当日の直前修正が確実に反映されるようにするため |

ビルドは不要。Node も npm もフレームワークも使っていない。

## 動かす

`index.html` をダブルクリックするだけで動く（`file://` で完結する）。
データを `fetch` ではなく `<script src="data.js">` で読んでいるのが理由で、
これは意図的な設計。ローカルサーバーは要らない。

### 日付タブ

画面上部に 8/28(金) / 8/29(土) / 8/30(日) のタブがあり、タップで表示する日を
切り替えられる。各タブにはその日の演舞件数が出る。

- 開いたときに選ばれる日は、**今日が開催日ならその日**、そうでなければ
  `defaultDate`（8/30）
- 実際の今日にあたるタブには ● が付く
- **選んだ日が実際の今日のときだけ**、「次の演舞まで◯分」「終わった演舞のグレーアウト」
  「次はここ」が働く。別の日を見ているときは全カードが通常表示になる
- タブは `?day=2026-08-29` という普通のリンクなので、リロードしても選択が残る

### 動作確認用のクエリ

| クエリ | 効果 |
|---|---|
| `?day=2026-08-29` | 表示する日（タブの選択そのもの） |
| `?now=14:35` | 現在時刻を上書きする |
| `?today=2026-08-30` | 今日の日付を上書きする |

例: `index.html?day=2026-08-30&today=2026-08-30&now=13:20`
（8/30 を当日として、13:20 時点の見え方を再現する）

`?now` か `?today` を使っている間は画面上部に黄色い「テスト表示中」バナーが出る。
本番でこのバナーが出ていたら URL からクエリを外すこと。`?day` だけなら出ない。

## スケジュールを入れる

`data.js` の `teams` と `performances` を書き換える。

```js
teams: [
  { id: "team1", name: "実際のチーム名", color: "#c2410c" },
  { id: "team2", name: "実際のチーム名", color: "#1d4ed8" },
],

performances: [
  { date: "2026-08-30", teamId: "team1", venueId: "hisaya_main", start: "14:20", end: "14:30" },
  { date: "2026-08-30", teamId: "team2", venueId: "oasis21",     start: "15:00", end: null,
    note: "この会場だけの注意書き。書かなければ何も出ない" },
],
```

- `date` は必須。書き忘れるとページ上部に警告が出て、その演舞は表示されない
- `venueId` は `venues` のキーをそのまま使う（`hisaya_main`, `oasis21` など）
- `end` がわからない演舞は `null` にする。`defaultDurationMin`（既定5分）で
  補われ、画面に「終了は推定」バッジが出る
- `note` は任意。交通規制など、その演舞にだけ効く注意をカードに黄色い枠で出す
- 書き換えたら `tests.html` を開いて全件パスすることを確認する。
  存在しない会場ID・中止会場の参照・時刻の書き間違いは、
  ページ上部に赤い警告として出る

### 終了時刻がわからないときの考え方

余裕 = 次の開始 − 前の終了 − 移動時間 なので、**演舞時間を短く見積もるほど
余裕が大きく出る**。つまり短すぎる既定値は「行けるはずが間に合わない」という
最悪の方向に外れる。`defaultDurationMin` は実際より少し長めにしておく。

## 判定のしくみ

```
徒歩   = ceil( 会場間の直線距離 × 1.3 ÷ 分速80m )
電車   = 会場から最寄り駅までの徒歩 + 待ち + 駅から駅の乗車 + 駅から会場までの徒歩
移動   = 徒歩と電車の速いほう（ただし電車が5分以上速くないと徒歩のまま）
余裕   = 次の開始 − 前の終了 − 移動
```

| 余裕 | 表示 |
|---|---|
| 20分以上 | ☀️😄 ばっちり |
| 10〜19分 | ⛅️😊 行ける |
| 0〜9分 | 🌧️😐 ギリギリ |
| 0分未満 | ⛈️😢 むずかしい |

同じ会場での連続は移動0分になる。開始時刻が完全に同じ2件には「同時刻・どちらか一方」の
印が付く。これは移動時間の問題ではなく、どうやっても片方しか見られないという意味。

### 徒歩の側

迂回係数 1.3 は、直線距離のままだと久屋大通公園（南北1km超）や地下街経由の
移動を過小評価するための補正。`data.js` の `detourFactor` で変えられる。

### 電車の側

電車は4つの足し算になっていて、それぞれの出どころが違う。

| 要素 | 出どころ |
|---|---|
| 会場 ↔ 最寄り駅の徒歩 | 公式の会場アクセス表記そのまま（`venues[].stationWalkMin`） |
| 待ち | `boardingWaitMin`（既定4分）。本数の少ない駅は `stations` で上書き（道徳は8分） |
| 駅から駅の乗車 | `stationRides` の実測値。乗り換えの待ちを含み、最初の1本の待ちは含まない |

`stationRides` は Yahoo!路線情報で 2026-08-25 に確認した所要時間で、
`checked: true` が実測、`checked: false` が実測値と駅数から割り出した推定。
**今回のスケジュールで判定に効く区間はすべて実測側に入っている**
（推定側が使われるのは栄↔矢場町のような1駅区間だけで、そこは徒歩が採用される）。

区間表に無い組み合わせは `transitFallback`（6分 + 直線km × 2.4分）で概算し、
画面に「区間データ未登録・概算」のバッジを出す。黙って徒歩に戻したりはしない。
新しい会場を使うことになったら、Yahoo!路線情報などで所要時間を調べて
`stationRides` に1行足すのがいちばん確実。

```js
"名古屋城|大須観音": { min: 12, via: "名城線 名古屋城→上前津 ／ 鶴舞線 上前津→大須観音", checked: true },
```

キーの向きは問わない（`app.js` が両方向を探す）。

### この見積もりで足りるか

余裕が判定の境目（0分／10分／20分）から10分以上離れていれば、
数分のずれで結論はひっくり返らない。今回のスケジュールで境目に近いのは

- 8/30 名古屋城 → 名駅JRタワーズ（余裕3分）
- 8/30 テレビ塔 → オアシス21（余裕5分）
- 8/30 どうとく → 名古屋城（9分足りない）
- 8/29 オアシス21 → イオン熱田（余裕16分。10分と20分の両方の境目から10分以内）

の4つで、残りはどれも十分に離れている。上の4つは当日の実測で判断する。

### Google マップへの逃げ道

各判定バンドに実測ルートへのリンクを置いてある。

- `🚶 徒歩ルート` … 移動がある区間すべてに出る
- `🚇 電車ルート` … 電車を採用した区間と、直線距離が `transitHintMeters`（既定1200m）を
  超える区間に出る

演舞カードの `🚇 電車で行く` / `🚶 歩いて行く` は、現在地からその会場への道案内を
それぞれのモードで開く。どちらで向かうかは会場によって変わるので選べるようにしてある。

人混み・交通規制・入場待ち・改札の混雑はどの見積もりにも入っていない。

各ページの Google マップリンクを展開して得た地点座標から作成済み。全16会場。
